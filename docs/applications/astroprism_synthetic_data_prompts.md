# AstroPrism synthetic-data prompts for the 646-candidate pilot

These are proposed reusable prompts and data contracts, **adapted for this project, not copied paper prompts**. They accompany the [training plan](astroprism_training_plan.md) and [evaluation plan](astroprism_benchmark_landscape.md). No synthetic records have been generated by this document.

Use the [646 positional candidates](astroprism_data/overlap_candidates_646.csv.gz), resolve physical identities and raw observations using the [data contract](astroprism_data.md), then split by physical source. A provisional split is **516 training / 65 validation / 65 test** if all 646 are eligible and grouping permits it; reductions and grouped-split deviations must be recorded. Existing image captions are candidate supervision, not verified ground truth. The earlier 10,000-training-galaxy design remains a later expansion.

The sequence is image-caption alignment while measuring spectral facts and generating spectral captions, followed by spectrum/joint caption alignment, instruction SFT, and a later verifier-grounded RL experiment. AION-1 Base stays frozen; its modality-specific image and spectrum codecs feed the shared encoder, followed by separate projectors into Qwen3-4B. Caption alignment initially trains projectors; SFT adds Qwen LoRA. These prompts do not launch any stage.

AstroSpecLM uses intermediate measured/catalog facts for conversations (Appendices A.2–A.3) and captions (A.5). Its main model uses SpecMAE plus SFT; caption alignment is an ablation training projector and LoRA. Our frozen-AION/projector-first schedule is an adaptation. [AstroSpecLM methodology](https://arxiv.org/html/2609.07102)

## Workflow and generation boundary

1. Retrieve each matched image, spectrum, and existing caption; confirm that they refer to the intended source and that the caption's crop/bands match the image actually presented to the student.
2. Audit the existing image captions with Prompts 1 and 5. Keep approved original captions; edit or regenerate only unsupported/incompatible ones, preserving the original and change provenance outside student text. Image alignment can begin on the training split while the spectral work proceeds.
3. Extract spectral facts with Contract 2 and generate spectrum-only captions with Prompt 3. Produce paired captions from independently supported image and spectral facts only after both views are available.
4. Train the spectrum projector and continue image/spectrum/joint alignment using their corresponding valid targets. Different captions and modality views remain descendants of the same split source.
5. Generate image-only, spectrum-only, and joint instructions with Prompt 4, verify with Prompt 5, then perform SFT. For this small pilot, start with one caption per available view and two accepted conversations per modality per training source, with approximately 20% containing short evidence/uncertainty follow-ups where supported. This gives a nominal 3,096 training conversations at 516 sources, subject to acceptance. Do not multiply paraphrases to imply a larger independent sample count.
6. Only after SFT evaluation, build the small verifiable task pool specified in Prompt 6 for a controlled RL experiment. Keep held-out source IDs and all their descendants outside the training/reward pool.

Freeze the split before new captions or conversations are generated. Training teachers must not inspect held-out examples for prompt tuning. Evaluation references require separately checked measurements and expert review; a generated held-out caption is not automatically an independent gold answer. Record generator version, decoding settings, prompt hash, source revision, exact input view and all filtering decisions.

## Shared contract: observations, references, and permissions

Create source-disjoint splits **before** generation; keep repeated observations of the same physical source together. Apply an additional sky/field separation where overlapping cutouts or observing conditions could leak between splits. Teachers may receive privileged reference information; the student receives only the declared observational inputs and ordinary conversation text.

Each example has three separate components:

1. `student_input`: image and/or observed-frame spectrum, public input metadata, and conversation history.
2. `teacher_reference`: typed facts, independently obtained supervision labels, and scientific constraints.
3. `audit_sidecar`: source IDs, fact IDs, measurement provenance, target permissions, claim-to-fact links, generator/verifier versions, and split membership. **Do not concatenate this sidecar into student prompts or targets.**

Minimal fact record:

```json
{
  "fact_id": "spec.continuum.001",
  "name": "descriptive_or_measured_property",
  "value": null,
  "unit": null,
  "uncertainty": null,
  "provenance": "image_pixels | spectral_measurement | catalog_label | supplied_metadata",
  "source_reference": "versioned_record_or_pipeline_output",
  "evidence_kind": "direct | derived | inferred | external_label",
  "required_student_inputs": ["spectrum"],
  "quality": "valid | low_confidence | unavailable",
  "status": "measured | upper_limit | not_detected | out_of_coverage | masked | not_assessed",
  "evidence_locator": {},
  "allowed_uses": ["caption", "grounded_explanation"],
  "restrictions": []
}
```

`evidence_locator` contains image regions/bands or observed wavelength intervals and relevant quality flags. Preserve original measurement units, conventions, uncertainty definitions, and extraction versions. A measured detection significance is distinct from a teacher's subjective confidence. Do not invent calibrated probabilities for VLM descriptions.

**Permission rule:** a fact is usable in a grounded description only when its required inputs are available and its scientific restrictions are satisfied. A catalog label may also be an explicitly authorized supervised prediction target, but that does not make it directly observed evidence. For example, image-only redshift estimation can use spectroscopic redshift as a training label; its answer must be framed as an estimate, and its explanation cannot claim to observe spectral lines. Keep these prediction tasks separate from observational captions.

**Processed-input rule:** admissibility refers to the exact processed student view, including crop, resize, selected bands, wavelength coverage, normalization, and supplied calibration metadata. A fact visible in a teacher’s larger image may fall outside the student’s calibrated four-band AION 96-by-96 crop. The teacher rendering is only a view of those bands, not a replacement for the calibrated student input. Add requirements such as `metadata.pixel_scale` or `metadata.flux_scale` when needed. Validate the fact after input transformations.

**Redshift rule:** when evaluating redshift inference, keep spectra in the observed frame. Do not feed the true redshift, true-redshift rest-frame transformations, answer-bearing filenames, or target-derived input features to the student. An independently inferred candidate redshift is a model/measurement output, not a hidden input. Line identifications used as supporting evidence must have defensible support; associations selected only by consulting the hidden answer must not be described as independent confirmation.

## Prompt 1 — Image fact extraction with a VLM

Teacher input: the actual image; declared band-to-channel mapping; pixel scale/WCS when available; image masks and quality flags. Omit answer-bearing catalog properties during this perception pass.

```text
You are extracting a conservative image evidence record for astronomical
training data. Inspect only the supplied image and declared image metadata.

Record visible source extent, shape, concentration, resolved structure,
relative appearance across supplied bands, nearby sources, and artifacts.
Distinguish observation from interpretation. “Unresolved source” does not
establish “star”; a color composite does not establish calibrated color.

Use coarse descriptive categories when appropriate. Do not invent numerical
photometry, angular sizes, redshift, stellar mass, spectral lines, or physical
classifications. Numerical measurements must come from a supplied documented
measurement; angular scale claims require valid scale metadata. Mark ambiguous
features as low confidence. Do not equate “not visibly resolved” with absent.

For each fact, return its image region/bands, evidence kind, quality, and
limitations. Set required_student_inputs=["image"]. Include only facts you can
support. Return strict JSON:
{"facts": [...], "image_quality": [...], "limitations": [...]}.
```

Review uncertain morphology facts before using them as categorical targets. A second VLM agreeing is useful screening, not scientific ground truth.

## Contract 2 — Spectrum facts from measurement code

**This is an extraction contract for deterministic, versioned analysis code, not a request for an LLM to invent measurements.** Existing trusted pipeline products can supply measurements when provenance and quality flags are retained.

Input: observed wavelength array, calibrated flux and units, inverse variance/uncertainty, valid-pixel mask, instrumental resolution, arm boundaries, sky/telluric flags, and declared calibration metadata. Do not silently impute missing wavelengths or treat zero weight as zero flux.

Output where measurable:

- Valid wavelength coverage, masked intervals, and documented continuum/quality summaries.
- Emission/absorption candidates with observed centroids, widths, integrated fluxes or equivalent widths, uncertainties, detection statistics, fit diagnostics, and evidence intervals.
- Defensible line identifications, competing identifications when ambiguous, and any independently inferred redshift with uncertainty and method.
- Line ratios and other derived quantities only when their components, units, uncertainty propagation, and required corrections are valid.
- Separate `not_detected`, `upper_limit`, `out_of_coverage`, `masked`, and `not_assessed`. Nondetection requires a valid search region and a documented detection threshold. An upper limit requires an explicit numerical method and confidence convention. Neither establishes physical absence.
- Separate external catalog labels from observation-derived measurements. Preserve aperture/fiber geometry; a spectrum may sample only part of an extended image source.

All thresholds, fit windows, quality rules, and uncertainty conventions belong in versioned configuration. The LLM receives measured facts and may verbalize them; it must not backfill missing numerical fields. Null means unavailable, not zero.

For this galaxy pilot, assess continuum shape, a valid 4000-Å break measure, and covered galaxy emission/absorption features. Suggested candidates include [O II], [O III], Hα/Hβ, [N II], [S II], Ca H/K, Mg b and Na D. This list is a measurement checklist, never evidence that every source contains these lines. Record blending and resolution limits rather than force individual detections. Stellar temperature and molecular-band tasks are outside the initial galaxy-only scope.

If the measurement pipeline uses a catalog redshift to select rest-frame windows, tag the result `conditioned_on_catalog_redshift=true` and retain the corresponding observed-frame interval. Such facts can supervise a description when their support is checked in the observed spectrum, but they are not an independent redshift recovery test. Keep catalog-redshift rest-frame arrays and selected-line identities out of the student inputs for redshift inference. Preserve the AION checkpoint's own preprocessing contract rather than substituting AstroSpecLM preprocessing.

For each candidate produce a machine-readable fact record even when no useful caption is possible. An unavailable measurement should reduce the task pool, not trigger an invented answer. Caption the training, validation and test sources in isolated split workflows; only training captions enter alignment. Expert-check evaluation facts independently of the training caption teacher.

## Prompt 3 — Stage 1 generative caption construction

Teacher input: `active_modalities`, admissible facts, modality-specific limitations, and optional image observation. Produce image-only, spectrum-only, and optionally paired captions. The training input contains the corresponding observation tokens and a short caption request; the target is the caption. Use next-token loss on the assistant caption.

```text
Write a concise observational caption for the declared student inputs.
Use only facts whose allowed_uses include caption and whose required inputs
are present. External catalog labels are not observational caption facts
unless the student explicitly receives that metadata and you identify it as
supplied information. Do not mention hidden labels, source IDs, fact IDs,
the reference table, or the data-generation process in the caption.

Describe 2–4 salient supported facts, preserving uncertainty and limitations.
Use numerical values only when measured and useful. Never replace missing
coverage with a nondetection. For paired inputs, attribute image findings to
the image and spectral findings to the spectrum; avoid unsupported physical
connections and account for aperture differences. Avoid generic filler.

Return strict JSON with two distinct fields:
{"student_caption": "...",
 "audit_sidecar": {"claims": [{"text": "...", "fact_ids": [...]}],
                   "active_modalities": [...], "limitations": [...]}}.
If no defensible caption can be written, return student_caption=null and a
rejection reason in audit_sidecar.
```

Sample student requests: “Describe the visible morphology in this image.” / “Describe the main features supported by this observed-frame spectrum.” / “Summarize what the image and spectrum each show.” Do not use the same caption unchanged for all three input conditions.

## Prompt 4 — Stage 2 instruction conversation construction

Teacher input: admissible image/spectral facts; separately marked supervised labels; available student inputs; task family; single- or multi-turn requirement; answerability policy. Teachers may use reference facts to write grounded answers, but the student must learn to recover the relevant information from its own inputs.

```text
Generate one scientifically grounded instruction-following training example.
Inputs specify active modalities, permitted tasks, reference facts, separately
authorized prediction targets, and single-turn or multi-turn format.

Choose a question that can be answered at the declared level of certainty.
Use an external label as an answer only for an explicitly authorized
supervised prediction task. Do not present that label as direct observational
evidence or construct an explanation that the available input cannot support.
Include a concise evidence summary when useful; do not invent reasoning,
measurements, causal mechanisms, or certainty. Do not output hidden reasoning
traces. Use ordinary observational language rather than fact IDs.

Image-only: use visible morphology and valid image measurements. Spectral
lines and exact catalog properties are not image evidence.
Spectrum-only: use measured spectral features and justified inferences;
do not describe morphology absent an image.
Joint: ask at least one question that uses information from both modalities,
or asks which modality supports each finding. Combining two facts does not
prove causation. Respect fiber/aperture mismatch and possible ambiguity.

For unanswerable/partially answerable examples, explain the specific missing
measurement or limitation and answer the supported part. Distinguish missing
coverage, low quality, upper limits, and nondetections. Do not invent an
insufficiency just to create a refusal.

For multi-turn examples, maintain the declared available modalities and all
prior stated facts. Vary follow-ups meaningfully: clarification, evidence,
uncertainty, or comparison. Record when an earlier turn reveals a target;
a later answer conditioned on that reveal is not independent prediction.
Do not put the desired answer or target-derived metadata into the question
for a task intended to evaluate independent estimation.

Return strict JSON:
{"student_messages": [{"role": "user", "content": "..."},
                      {"role": "assistant", "content": "..."}],
 "audit_sidecar": {"task_family": "...", "active_modalities": [...],
 "answerability": "full | partial | insufficient",
 "claims": [{"turn": 1, "text": "...", "fact_ids": [...],
             "use": "observation | inference | supervised_label"}],
 "conditioning_on_prior_targets": [], "limitations": [...]}}.
```

Grounded question patterns, instantiated only when the record supports them:

- **Image:** “What visible structure does the source have, and which features are uncertain?”
- **Spectrum:** “Which measured features support your interpretation, and what does the data quality prevent you from concluding?”
- **Joint:** “How does the image morphology complement the spectral characterization? State the evidence from each and any aperture limitation.”
- **Partial answer:** “Can these inputs establish this requested property? Explain the information that is present and the measurement still needed.”
- **Follow-up:** “Which observation supports that statement?” / “How strong is the evidence?” / “Would the conclusion remain supported if only the image were available?”

Use both single-turn and multi-turn records. Set mixture proportions after measuring coverage and difficulty, rather than presenting arbitrary ratios as established scientific practice. Mask user/instruction tokens in the supervised loss; audit sidecars never enter the student sequence. With modality dropout, select or regenerate a valid target for the remaining inputs; blindly reusing a joint answer can manufacture hallucination training.

## Prompt 5 — Independent verification and filtering

Use a separate verifier pass with access to the original observations where it can assess them, measurement outputs, provenance, permissions, student inputs, and the candidate record. Numerical consistency, schemas, split integrity, forbidden metadata, and coverage/detection rules should also be checked in code. A model verifier does not replace independent expert evaluation.

```text
Audit this generated training record against the exact student-visible inputs
and the supplied evidence. Treat the candidate answer and its claimed fact
links as untrusted. Use only evidence retained in the student’s processed inputs and visible
calibration metadata. Check every scientific assertion, numerical value/unit,
uncertainty, modality attribution, and limitation. Flag external labels
presented as observations, unsupported causal stories, unjustified precision,
false nondetections, and target leakage through inputs or earlier turns.

Check that the question is useful and answerable as labeled. For joint tasks,
check whether both modalities actually contribute. Relevance to both does
not mean the observations prove the same property. Flag aperture mismatch
where it changes the interpretation. Do not infer that mismatched inputs
must be detectably inconsistent; some mismatches are observationally ambiguous.

Return strict JSON:
{"decision": "accept | revise | reject",
 "checks": {"schema": true, "supported_claims": true,
            "modality_permissions": true, "numeric_consistency": true,
            "uncertainty": true, "answerability": true,
            "no_target_leakage": true, "conversation_consistency": true},
 "issues": [{"code": "...", "severity": "error | warning",
             "turn": 1, "claim": "...", "reason": "...",
             "fact_ids": [...]}],
 "requires_expert_review": false,
 "revision_instructions": []}.
Do not silently rewrite a faulty record and mark it accepted. Revisions must
be regenerated and verified again. Reject examples whose required evidence
cannot be established; do not fabricate evidence to rescue them.
```

## Prompt 6 — Later verifiable task construction for RL

This is a proposed data contract for the stage **after SFT**, not a claim that RL is implemented or justified by the present sample size. Use only training-source observations. A reward is eligible only when a versioned independent checker can assess the requested answer from trusted labels or measurements. Suitable initial tasks include a measured numerical property with a fixed tolerance, a covered line-state classification, or attribution of a known supported feature to the correct modality. Avoid broad physical interpretations for which the checker cannot establish correctness.

```text
Construct one short task for a verifier-grounded reinforcement-learning pool.
You receive training-source observations, vetted facts, and an explicit list
of available deterministic verifier functions. Select only a task supported
by these inputs and one of those functions. Do not invent a checker, a target,
a tolerance, or a human-agreement score. The reward specification is private
supervision and must never be included in the student's question or context.

Give the question, student-visible modalities/metadata, structured answer
schema, and the exact authorized verifier identifier and target reference.
Use the supplied units, tolerances and quality requirements unchanged.
If the answer cannot be independently verified, return eligible=false.
If a task is intended to assess insufficiency, its coverage/quality rule must
be explicit and independently checkable; do not label an arbitrary unknown
property as unanswerable just to create a rewardable refusal.

Return strict JSON:
{"eligible": true,
 "student_question": "...",
 "student_inputs": ["image", "spectrum"],
 "answer_schema": {"answer": "...", "unit": "..."},
 "private_reward_spec": {"verifier_id": "...", "verifier_version": "...",
   "target_reference": "...", "tolerance_reference": "...",
   "quality_rule_reference": "..."},
 "audit_sidecar": {"source_split": "train", "fact_ids": [...],
   "task_family": "...", "limitations": [...]}}.
```

Implement and unit-check the reward independently of the generator. Scientific correctness should dominate; schema compliance is a small auxiliary signal, not a substitute for correctness. Log parse failures and check reward edge cases, unit conversions, boundary values and empty answers. Do not reward answer length, persuasive prose, agreement with the same teacher, unsupported explanations, or student self-assessment. When an answer has a correct scalar and an unverifiable explanation, do not treat the scalar's reward as validation of that explanation.

Start from the saved SFT checkpoint. For the first RL pilot, freeze AION and the aligned projectors/type embeddings and update only Qwen LoRA, matching the training plan. Select the algorithm and regularization against the SFT reference only after validating the reward and Aurora runtime; no PPO/GRPO implementation is assumed here. Compare SFT and RL checkpoints on the same locked independent test set and separate reward score from scientific quality. With approximately 516 training galaxies, monitor memorization and retain SFT as the default if the RL pilot does not improve held-out results.

## Evaluation boundary

Evaluate on held-out physical sources with original data and independently checked targets, including an expert-audited explanation set. Report quantitative task accuracy and calibration separately from prose quality. Include image-only, spectrum-only, joint, and language-only controls; remove/swap relevant modalities and mask scientifically relevant evidence. A teacher/verifier agreement rate is a data-quality screening measure, not proof of astrophysical correctness or successful cross-modal reasoning.

For incremental conversations, an answer may use only observations introduced by that turn. The first implementation places both observations before the conversation; it cannot claim a test in which the spectrum becomes available only later without implementing and checking the intended causal positions. See [evaluation and interleaving contracts](astroprism_benchmark_landscape.md).
